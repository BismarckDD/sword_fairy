# 开场与剧情过渡显示修复（2026-10-16）

开场字幕通过原版 BIOS 定时事件推进，CD 音频通过实际时间播放。原窗口每收到一次 Windows 定时消息只产生一个 BIOS tick；消息延迟和合并会让字幕累计落后。现在根据经过时间按 1193182 / 65536 Hz 产生 BIOS tick，保留原版字幕、等待时长和剧情状态。

非战斗动画使用的毫秒等待不经过输入轮询，原宿主因此无法处理窗口绘制。现在在宿主时钟服务中处理窗口消息，使 ANM 播放期间可以显示中间帧并响应关闭。

调色板淡出、淡入原本等待 VGA 垂直刷新，但宿主直接返回“刷新完成”，导致 64 次调色板变化瞬间结束。现在交互运行以高精度时钟等待约 70 Hz 刷新，并在完整调色板写入后立即绘制。窗口存续期间申请 1 ms 系统计时精度，关闭时释放。无窗口和自动剧情验证继续使用原有确定性设备边界。

## original 对照

- `original` 是冻结的还原工程与资源包，不是原作者源码；本次保留其全部文件。
- 红衣人出场在 `events_005.c` 的 `jx_event_005_0594` 中已调用 `2F28:7062` 播放 `ani000.anm`，随后才启用人物显示及战斗。资源和动画调用均存在，缺失的是动画播放期间的窗口刷新。
- 刘轻舟对应的衡山大厅流程为 `events_early.c` 的 `jx_event_006_0000`。它在对话结束后调用淡出，集中改变 `6678..667E` 等人物显示标记，刷新场景，再淡入。当前脚本与 `original/源码/src/events_early.c` 的文本一致。集中切换属于冻结原逻辑；无遮掩的突然消失来自宿主跳过淡出淡入，不另加离场动作。

## 开场启动偏差微调

用户复测反馈画面略快于配音。检查发现，开场配音的同步读取、缓冲复制及音频设备初始化期间不处理 BIOS tick，随后窗口轮询会补发这段时间的事件，使字幕提前。现在仅在开场旁白音轨（原脚本的音乐偏移 22）成功提交播放时，对齐 BIOS 时钟，保留已经发出的 tick，丢弃准备音频期间的积压和不足一 tick 的相位。其他音乐、普通游戏时钟和 VGA 刷新时钟不变；没有增加固定延时或改变原版字幕速度。

追加测试模拟 330 ms 音频准备，确认对齐后不补发字幕事件，60 ms 后正常产生下一 tick。严格构建、窗口计时测试、真实资源红衣人流程回归及源码检查通过。音频输出设备的实际缓冲延迟仍需人工复测；本次对齐点为提交播放，尚未改为声卡实际播放位置。
