# 衡山大地图：从上下文重绘反取共享图块的实验

## 320×320 分块：原生 AI 接近四倍细节

为解决前轮原生输出只有约二倍、再插值导致发糊的问题，新增 `--chunk-size 320`。本地资源单独保存到 `runtime/game/hd/maps/context-tiles/HENS00-320/`，保留前轮实验供比较。

衡山主图导出 20 个真实 320×320 窗口。横向起点为 0、320、640、960；纵向为 0、320、640、960、1120。末行向地图内贴齐，保持真实上下文。全部窗口交给内置 imagegen 原生重绘，要求约 1280×1280，重点为清晰的瓦片、岩石、枝叶、木纹及地面细节。

首块模型原生返回 1254×1254，即源图每轴约 3.92 倍。`--allow-near4x` 仅接受原生尺寸落在精确四倍目标以下 3% 以内的正方形，拒绝大幅插值或缩小。1254→1280 只用最近邻做约 2.1% 的整数图块坐标对齐，检查原生每行、每列全部保留；不进行平滑、锐化或融合。AI 原生输出独立保留。

反取仍选择一张实际候选作为共享 64×64 图块，不平均多张图、不混合纹理；程序逐图块比较非透明像素，验证切片过程中未改写被选 AI 像素。前景遮罩与双层索引保持原版。地图重叠处按窗口顺序覆盖，不用模糊渐变掩盖接缝。

```powershell
python tools/experiment-context-tiles.py prepare --chunk-size 320
# 将 20 张原生 AI 输出按 plan.json 编号保存到 generated/
python tools/experiment-context-tiles.py finish --chunk-size 320 --allow-near4x
python tools/compare-context-tile-detail.py
```

`previews/640-vs-320-native-detail.png` 对比同一位置的前轮约二倍原生细节和本轮约四倍原生细节，展示时均只用最近邻对齐。约四倍输出仍不自动等于几何与文字精确复原，正式接入需要另外检查拼接与遮挡。

## 流程

1. 解码原始 HENS00.BLK 与地图双层索引，逐像素重建并核对原始地图。
2. 1280×1440 地图按 640×640 窗口导出。横向起点为 0、640；纵向为 0、640、800。末行向内贴边，避免填充地图不存在的内容；窗口起点均对齐 16 像素网格。
3. 每块分别通过内置 imagegen 参照原图重绘，要求 2560×2560，保存原始输出和提示词。
4. 严格模式拒绝尺寸不为 2560×2560 的生成图。显式 `--diagnostic` 允许插值以诊断图块提取和复用问题，但输出不算通过原生四倍分辨率验收。
5. 按已知地图坐标反取 64×64 候选图块，不做模糊图像匹配。背景候选必须没有被前景遮挡；前景只取自身原始非透明像素。原始透明掩码以最近邻放大保持。
6. 同一编号有多个候选时，计算其 16×16 色彩特征，选择最接近中位数特征的一张实际候选，不混合不同上下文。报告保存候选数量、选择位置及差异。
7. 创建独立的 64×64 素材库，再按原始双层索引重建整图。缺少候选的图块明确使用原像素四倍回退，不计入重绘完成数。

## 覆盖限制

衡山库有 483 个图块，主图引用其中 440 个。424 个有可见候选，43 个未使用，15 个始终受遮挡，1 个全透明。只有 HENS00 使用这个 BLK。因此仅凭主图的合成画面，不能完整恢复素材库；未使用和被遮挡的图块需要额外参考或单独构建上下文。

生成式重绘可能改变微小物体、轮廓与几何位置；输出像素尺寸正确不等于细节无损。将不同上下文的候选压成一个共享图块，还会舍弃上下文变化，并可能造成接缝。本实验保留直接拼图和共享图块拼图用于比较，不自动覆盖正式游戏资源。

## 本轮实际结果（2026-10-21）

六张内置生成图实际均为 1254×1254，没有达到原生 2560×2560。严格模式按预期拒绝；对照图仅在显式诊断模式下插值生成，不能认定为用户要求的四倍无损重绘。

反取获得 424 个有可见样本的非透明图块；56 个非透明图块使用原像素回退，另有 3 个全透明槽位。独立 `candidate-pack/` 包含 483 张 64×64、32 位 BMP 及原始索引参考，但未安装到正式游戏。双层索引重建整图为 5120×5760。

共享图块重拼的格边平均 RGB 跳变为 25.49，直接上下文拼图为 11.68（0–255 色值量纲）；约为 2.18 倍。该指标是接缝诊断，不是细节保真度证明。对照中可见地面色块、瓦片与山石边缘断接，说明本次候选压回单一共享图块后尚不能满足画质要求。

输出包括 `previews/comparison.png`（左原图、中直接拼图、右共享图块重拼）、`previews/architecture-detail.png`、`replacement-library-64.png`、`reconstructed-shared-tiles-4x.png`、`prompts.txt`、`report.json`。后续若沿此路线改进，需要解决原生尺寸控制、生成图与原图格子的精确配准、重复图块及其邻接边界约束，并补足缺失上下文。

## 重跑

```powershell
python tools/experiment-context-tiles.py prepare
# 将六张原始生成图按 plan.json 中编号放入 generated/
python tools/experiment-context-tiles.py finish
# 仅在明确进行诊断时：
python tools/experiment-context-tiles.py finish --diagnostic
```

`report.json` 分别记录原生尺寸达标、是否插值、原始资源完整性和覆盖情况；`zero_detail_loss_verified` 不会因为尺寸或哈希校验通过而变成 true。实验没有修改引擎、原始档案、正式素材清单或存档。
