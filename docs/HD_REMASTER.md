## 当前进度

- 2026-10-17 按用户要求暂停高清显示改造，恢复默认 960×600 客户区及原先铺满窗口的显示方式。1280×960、4:3 黑边与窗口尺寸限制改动均已撤回；其他菜单、存档和计时修改保留。
- 撤回前已备份代码、文档、工具、测试、运行目录（含存档）、构建程序及高清预览到 `runtime/backups/before-hd-rollback-20261017-112619/`，共 999 个文件，附 SHA256 清单。备份未包含 original 归档、编译缓存、Git 历史和 runtime 根目录的光盘音乐；这些文件未修改。
- 目前游戏画面仍由原版索引色素材绘制。这是显示基础改造，不代表高清素材已经接入。
- `tools/export-hd-assets.ps1` 盘点运行目录根文件及 FIGHT、VOC，输出本地清单和静态 IMG 预览。不会修改源资源；输出不包含存档和内存快照。
- 仅对 IMGV 头、16 字节头部、末尾 768 字节调色板且像素区大小完全匹配的文件导出预览。透明索引按原色显示；调色板解释和多帧顺序需逐项核对。ANM、地图、角色打包资源暂未解码。
- 首次本地盘点为 407 个文件，71 个文件成功导出 71 张预览，6 个 IMG 头不支持、2 个 IMG 布局不支持，其余 328 个文件尚未解码；这不是全游戏动画帧数。
- 第一张美术候选为 `runtime/hd-analysis/candidates/begin-v1.png`，由内置 imagegen 参考 BEGIN.IMG 制作。工具实际返回 1448×1086（4:3），不是 1280×960 生产图。尚未接入游戏，后续需按目标输出尺寸制作并核对构图、画风与淡入淡出。

## 本地使用

```powershell
./tools/export-hd-assets.ps1
./scripts/build.ps1 -Zig ./.cache/build-tools/ziglang/zig.exe -Target Game
```

素材清单位于 `runtime/hd-analysis/inventory.json`，图集位于同目录 `index.html`。生成素材仅放在忽略的 runtime 目录，不加入源码仓库。构建产物位于 build；此阶段不自动覆盖运行目录里的旧程序。

## 高清资源契约（待实现）

高清资源包计划放在 `runtime/game/hd/`，通过清单独立加载，禁止写入旧 16 位图像缓冲区。每条资源需包含：

| 字段 | 用途 |
| --- | --- |
| source、frame | 原资源相对路径和从零开始的帧号 |
| image | 高清 PNG 相对路径 |
| source_rect | 原图裁剪范围 |
| logical_size | 原逻辑坐标中的宽高 |
| anchor | 原逻辑坐标中的脚底或绘制基准 |
| palette_policy | 原调色板变化、淡入淡出如何作用到高清图 |

缺失或无效的高清条目必须回退原图。320×200 坐标映射至 1280×960 为 x×4、y×4.8；矩形左右、上下边界分别转换后求尺寸，防止独立取整产生接缝。640×480 模式为两轴×2。第一版不改变游戏逻辑、存档和动作时间。

## 绘制接入顺序

1. 静态全屏图：跟踪资源加载和页面身份，在合成前提供替换入口。
2. 头像：`events_portrait.c` 中原图为 60×70，按角色编号替换；先验证对话遮盖、背景恢复。
3. 字体和菜单：捕获文字内容与布局，高清层重新绘制；不能把原图中的文字当作高清字形。
4. 场景与人物：保留地图格、脚底位置及遮挡顺序；处理滚屏、局部更新和页面备份。
5. 战斗与剧情动画：按原帧号同步高清帧；补齐透明合成、调色板过渡、水波和卷屏。

仅在最终窗口画面上覆盖背景会遮住角色或菜单，也无法可靠识别资源，因此不作为正式替换实现。
